# 认证状态管理配置说明

## 配置项位置

文件：`conftest.py` 第 19-30 行

```python
# ========== 认证状态管理配置 ==========

# 认证状态有效期（秒）
AUTH_STATE_EXPIRY = 60 * 60  # 1 小时

# 是否启用认证状态在线验证
ENABLE_AUTH_VALIDATION = False  # False = 跳过在线验证（推荐）
```

---

## 配置说明

### ENABLE_AUTH_VALIDATION

控制是否在测试前打开临时页面验证认证状态。

| 值 | 行为 | 优点 | 缺点 |
|---|------|------|------|
| `True` | 每次运行测试前，打开临时页面验证 cookies 是否有效 | 更安全，确保 cookies 未失效 | 每次运行多打开一次页面，较慢 |
| `False` | 只检查文件存在性和过期时间，不验证 cookies | 更快，不会多打开页面 | 如果 cookies 提前失效，可能导致测试失败 |

**推荐值**：`False`

## 什么时候需要启用在线验证？

建议在以下情况下启用（`ENABLE_AUTH_VALIDATION = True`）：

1. **调试认证问题**
   - 怀疑 cookies 提前失效
   - 需要确认登录状态是否正常

2. **CI/CD 环境**
   - 需要更严格的验证
   - 可以接受额外的时间开销

3. **长时间未运行测试**
   - 超过 1 小时没运行过测试
   - 不确定认证状态是否有效

**日常开发建议**：保持 `False`，节省时间。

## 其他配置项

### AUTH_STATE_EXPIRY

认证状态文件的有效期（秒）。

```python
AUTH_STATE_EXPIRY = 60 * 60  # 1 小时
```

**调整建议**：
- 如果你的网站 token 有效期是 2 小时：`AUTH_STATE_EXPIRY = 2 * 60 * 60`
- 如果是 30 分钟：`AUTH_STATE_EXPIRY = 30 * 60`

**效果**：
- 超过这个时间，会自动重新登录
- 在这个时间内，会复用现有的认证状态

## 常见问题

### Q1: 设置为 False 后，如果 cookies 失效怎么办？

**答**：测试会失败，但会清楚地看到错误信息。此时可以：
1. 删除 `test_data/auth_state.json`
2. 重新运行测试，会自动重新登录

或者临时启用在线验证：
```python
ENABLE_AUTH_VALIDATION = True  # 临时改为 True
```

### Q2: 如何判断是否需要启用在线验证？

**答**：如果你的测试经常出现以下错误，可能需要启用：
- "未找到'用药记录'按钮"
- 登录页面意外出现
- 认证失败错误

### Q3: 为什么不默认启用在线验证？

**答**：
- 大多数情况下，文件过期检查就足够了
- 在线验证会增加 15-20 秒的额外时间
- 影响开发体验（每次运行都要等待）

### Q4: 两种模式都试过，还是每次都登录怎么办？

**答**：检查以下几点：
1. 确认 `auth_state.json` 文件有 cookies（运行诊断工具）
   ```bash
   python3 scripts/check_auth_state.py
   ```

2. 检查认证状态有效期
   ```bash
   # 查看文件年龄
   stat -f "%Sm" test_data/auth_state.json
   ```

3. 查看测试日志，确认是哪个检查失败了

---

## 总结

| 场景 | 推荐配置 | 说明 |
|------|---------|------|
| 日常开发 | `False` | 更快，不影响开发体验 |
| 调试认证问题 | `True` | 确保 cookies 有效 |
| CI/CD | `True` | 更严格的验证 |
| 长时间未运行 | `True` | 确认状态是否仍然有效 |

**现在的默认配置（False）适合日常开发使用。**
